学习动机

2/55

关于动机 1/5

招聘研究助理时，成绩通常不是最重要的指标；想象力、抱负、主动性、好奇心和驱动力更能预测一个人是否能做出有用的工作。
  • 课程成绩与能力有相关性，但并不能完整衡量创造力和主动性。
  • 真正的突破常常发生在自发探索和课外项目中。
  • 学习 C++ 需要完成课程任务，也需要持续判断什么问题真正重要。
3/55

关于动机 2/5

  • 学业优秀并不强烈预测职业优秀，尤其在毕业数年后更是如此。
  • 考试成绩很少直接评估创造力、领导力、团队协作和复杂社会能力。
  • 职业成功往往不只是找到正确答案，而是找到值得解决的正确问题。
4/55

关于动机 3/5

  • 追求全 A 往往鼓励遵从规则；有影响力的职业生涯更需要原创性。
  • 如果目标只是成绩单无瑕，学生更容易选择简单课程并停留在舒适区。
  • 适度承担失败风险，可以积累面对挫折的经验，形成韧性。
5/55

关于动机 4/5

  • 只追求高分可能会牺牲社交、社团、志愿活动和长期友谊。
  • 课程学习很重要，但不应该挤掉所有探索和真实实践。
  • 原材料引用 Adam Grant 在《纽约时报》关于 GPA 与职业成功关系的讨论。
6/55

关于动机 5/5

  • STEM 对所有人都难，困难本身不是退出的理由。
  • 长期来看，好奇心和坚持往往比单次成绩更重要。
  • 原材料引用 NASA Mars Science Laboratory 首席软件工程师 Ben Cichy 的经历。
7/55

关于编程 1/2

  • 编程的吸引力在于：你创建一个小宇宙，然后让它按你的指令运行。
  • 优秀程序员不只为了报酬或赞美写程序，也因为编程本身有趣。
  • 编程是一种基于逻辑的创造性工作。
8/55

关于编程 2/2

  • 创造力：用新方式理解问题，并提出原创解决方案。
  • 艺术形式：代码和算法也能呈现优雅与美感。
  • 学习：编程让人每天学习新知识、提升技能。
  • 挑战：编程是与自己、问题和环境之间的持续挑战。
9/55

知识与经验的关系

  • 知识需要通过实践转化为经验。
  • 经验又会反过来帮助筛选、组织和深化知识。
  • C++ 学习尤其依赖这种循环，因为语言细节与工程上下文强相关。
10/55

学习与思考

在软件开发中，学习不是工作的一小部分；学习就是工作本身。
编程不是打字，而是思考。
  • 学习现代 C++ 时，应该把重点放在模型、语义、约束和权衡上。
  • 语法只是入口，思考才是核心工作。

C/C++ 编程语言简史

11/55

汇编语言

  • 汇编指令非常简单，但完成简单任务也需要大量代码。
  • 汇编几乎能表达计算机能做的一切，但读写困难。
  • 大量冗余和重复劳动会导致枯燥的编程体验与更多缺陷。
main:
    push rbp
    mov rbp, rsp
    call printf
    ret
12/55

C 语言简史 1/3

  • 1969 年，Dennis M. Ritchie 和 Ken Thompson 在 AT&T 贝尔实验室开发 UNIX。
  • 早期 UNIX 主要使用汇编编写，也包含 Fortran 和 B 语言解释器。
  • B 语言提高了开发效率，但缺少数据类型和结构体等能力。
  • 这些不足促使 Dennis Ritchie 设计 C 语言；ANSI C 最终标准定义于 1988 年发布。
13/55

C 语言简史 2/3

Dennis M. Ritchie 与 Ken Thompson 是 C 和 UNIX 历史中的核心人物。

#include <stdio.h>

int main() {
    printf("Hello World\n");
}
14/55

C 语言简史 3/3

  • C 被广泛用于操作系统、游戏、图形程序、工业系统和嵌入式系统。
  • C 的设计强调接近硬件、运行效率和可移植性。
  • C 同时也把许多底层责任交给程序员，这影响了后续 C++ 的设计取舍。
15/55

C++ 简史 1/3

  • C++ 最初名为 “C with Classes”，由贝尔实验室的 Bjarne Stroustrup 设计。
  • Stroustrup 于 1979 年开始这项工作。
  • 名称中的 ++ 来自 C 语言的自增运算符，暗示它是 C 的增强。
16/55

C++ 简史 2/3

  • C++ 的根源包括 C、Simula、Algol 等语言思想。
  • 它把低层控制能力与更高层抽象机制结合起来。
  • 这种组合让 C++ 既能靠近硬件，也能表达复杂软件结构。
17/55

C++ 简史 3/3

  • C++ 经历了长期演化，从早期面向对象扩展发展为多范式系统语言。
  • 现代 C++ 标准持续加入泛型、并发、编译期计算和库能力。
  • 学习现代 C++ 需要理解历史包袱，也要理解新标准带来的抽象方式。
18/55

关于演化

如果你今天教的内容和五年前完全一样，要么这个领域已经停滞，要么你自己停滞了。
  • C++ 不是静态语言，它持续随硬件、软件工程和标准演化。
  • 课程需要覆盖历史基础，也需要覆盖当代实践。

应用领域与流行度

19/55 - 21/55

流行编程语言榜单

  • 课件引用 IEEE Spectrum、TIOBE 和 RedMonk 等榜单展示语言流行度。
  • C++ 长期保持高可见度，尤其在性能敏感和系统级领域。
  • 榜单只能反映某些维度，不能替代对应用场景的工程判断。
22/55 - 23/55

为什么 C++ 如此流行

  • 全球可能存在数千亿行 C/C++ 代码，历史资产巨大。
  • 性能是 C++ 的定义性特征之一。
  • C++ 支持从低功耗嵌入式设备到大型超级计算机的广泛平台。
  • C++ 是多范式语言，允许在高层抽象和底层控制之间切换。
24/55 - 25/55

C++ 的应用领域

  • 操作系统：Windows、Android、OS X、Linux。
  • 编译器：LLVM、Swift 编译器。
  • 人工智能：TensorFlow、Caffe、Microsoft Cognitive Toolkit。
  • 科学计算：CERN、NASA、SETI@home、Folding@home。
  • 数据库：MySQL、ScyllaDB。
  • 游戏与引擎：Unreal Engine、Unity。
26/55 - 27/55

C++ 为什么重要

  • 历史上的性能缩放趋势正在放缓，算法设计越来越受性能限制影响。
  • AI 模型规模增长远快于传统摩尔定律速度，工程效率和硬件利用率更关键。
  • 当性能成为产品能力边界时，C++ 的控制力仍然有重要价值。
28/55 - 31/55

性能

  • 课件用 N-body simulation、语言 benchmark 和 Hello World 等例子讨论性能差异。
  • 性能比较需要关注工作负载、运行环境、编译器优化和测量方法。
  • C++ 常用于需要低延迟、高吞吐或可预测资源使用的场景。
32/55 - 35/55

表达力、内存、能耗与 CO2

  • 语言的表达力和运行效率之间常存在权衡。
  • 内存占用会影响成本、性能和可部署性。
  • 能耗与碳排放也是高性能计算和大规模服务中的工程指标。
  • 高性能不是只为了快，也关系到资源效率和环境成本。

C++ 哲学

36/55

C++ 哲学：性能 1/3

  • 除非别无选择，不应牺牲性能。
  • 零开销原则：不使用某个抽象时不应为它付费；使用时也应接近手写底层代码的成本。
  • 高层抽象和底层效率不是必然冲突，C++ 的目标是尽量同时满足两者。
37/55

C++ 哲学：类型安全 2/3

  • 只要可能，就在编译期强制安全性。
  • C++ 是静态类型语言，编译器可以在运行前捕获大量类型错误。
  • 类型系统也是表达设计意图和约束的重要工具。
38/55

C++ 哲学 3/3

  • 编程模型强调分层和局部化复杂性。
  • 只有当新特性解决实际问题时才加入语言。
  • 在约束条件下追求可预测运行时，不依赖垃圾回收。
  • 给程序员完整控制权，同时也要求程序员承担更多责任。
39/55

C++ 适合谁

C++ 适合那些想很好地使用硬件，并通过抽象管理复杂性的人。
  • 这门语言特别适合需要理解性能、资源和抽象成本的开发者。
  • 它不是最简单的入门语言，但非常适合系统性理解软件与硬件的边界。
40/55

C++ 的弱点

41/55 - 42/55

为什么 C++ 困难

  • C++ 很难作为第一门编程语言教学，因为它同时包含多种语言风格。
  • 语言规模大，既有 C 兼容特性，也有现代抽象机制。
  • 程序员需要理解对象生命周期、内存、类型推导、模板、重载和未定义行为等多个层面。
  • C++ 可以降低犯错概率，但一旦犯错，后果可能很严重。
43/55 - 44/55

C++ 的弱点

  • 向后兼容意味着危险默认行为和来自 C 的旧构造很难移除或彻底修改。
  • 复杂性来自历史、性能目标、兼容性和多范式能力的叠加。
  • 语言委员会需要在修复问题、保持兼容和推动演化之间持续权衡。

C++ 替代语言

45/55

Rust

  • Rust 1.0 发布于 2015 年，长期在 Stack Overflow 调查中拥有很高喜爱度。
  • Rust 与 C++ 一样关注性能和零成本抽象。
  • Rust 的核心目标之一是预防许多 C++ 常见漏洞，尤其是内存相关错误。
  • 代价是更严格的所有权和借用模型，需要开发者改变设计习惯。
46/55

Zig

  • Zig 发布于 2016 年，是一种极简开源系统编程语言，可视作 C 的替代候选。
  • 它支持编译期泛型、反射与求值、交叉编译和手动内存管理。
  • Zig 设计上强调与 C 的互操作性，并试图减少隐藏控制流和隐藏分配。

为什么切换到新语言很难

47/55 - 49/55

迁移障碍

  • 不存在完美语言，总会有更新、更闪亮的语言出现。
  • 组织内所有开发者同时切换语言非常困难。
  • 已有数千亿行代码需要互操作，不能简单抛弃。
  • 安全语言的运行时开销、边界检查成本和生态成熟度都需要评估。
  • 工具链、依赖、构建系统、招聘和培训成本也会影响迁移决策。
50/55

语言复杂度

每一秒花在理解语言上的时间，都是没有花在理解问题上的时间。
  • 语言复杂度会直接消耗认知预算。
  • 现代 C++ 学习的目标之一，是把复杂性整理成可使用的模型。

课程说明

51/55 - 54/55

课程目标与组织

  • 课程更准确的名称应是“现代 C++ 编程导论”。
  • 许多主题本身都有专门书籍，本课程只能在有限时间内建立整体框架。
  • 主要目标是帮助已有 C/C++ 和面向对象经验的学习者达到熟练 C++ 编程水平。
  • 课程组织为 29 讲，约 2000 页幻灯片。
  • 内容覆盖基础语义、面向对象、模板、翻译单元、编码规范、调试测试、生态、标准库、优化和软件设计。
