编辑器、IDE 与编译器

10/25

应该使用什么编译器

  • MSVC：Microsoft 提供的 C++ 编译器。
  • GCC：GNU Compiler Collection，包含 Linux 上最常见的 C++ 编译器。
  • Clang：基于 LLVM 基础设施，支持 Linux、Windows 和 Apple 平台。

Linux 初学者推荐 Clang：性能与 GCC/MSVC 接近、内存占用较低、诊断信息清晰、标准符合性严格，并包含 sanitizer、静态分析、自动格式化和 lint 等工具。

11/25

在 Linux 上安装编译器

大多数 Linux 发行版默认提供 gcc/g++。如需在 Ubuntu/Debian 上安装较新 GCC，可参考：

sudo add-apt-repository ppa:ubuntu-toolchain-r/test
sudo apt update
sudo apt install gcc-14 g++-14
gcc-14 --version

Clang/Clang++ 可按 LLVM 官方说明安装最新版本。

12/25

在 Windows 上安装编译器

  • Microsoft Visual Studio：安装 Visual Studio Community，并选择 C++ 桌面开发相关组件。
  • Clang on Windows：可通过 Windows Subsystem for Linux（WSL）或 LLVM Windows 包使用。
  • Windows 用户通常从 Visual Studio 或 WSL 起步最稳妥。
13/25

流行 C++ IDE

  • Microsoft Visual Studio：Windows 上最流行的 IDE 和 MSVC 编译器组合。
  • CLion：功能强大的跨平台 IDE，非商业使用免费。
  • Qt Creator：速度较快的 C++ IDE，常用于 Qt 项目。
14/25

图形界面代码编辑器

  • Visual Studio Code：轻量、插件生态丰富。
  • Cursor：基于 VS Code 的 AI 辅助代码编辑器。
  • 编辑器需要配合编译器、构建系统、调试器和 C++ 语言服务才能形成完整环境。
15/25 - 16/25

文本编辑器与开发者调查

  • Vim、Emacs、NeoVim 等文本编辑器非常强大，但需要更多配置经验。
  • 工具选择没有唯一答案，应结合平台、团队、项目构建系统和个人熟悉程度。
  • Stack Overflow Developer Survey 可作为观察工具流行度的参考，但不应成为唯一依据。

如何编译

17/25

选择 C++ 标准版本

可以显式指定 C++ 标准版本来编译 C++11、C++14、C++17、C++20、C++23 或 C++26 程序。

g++ program.cpp -o program
g++ -std=c++14 program.cpp -o program
g++ -std=c++20 program.cpp -o program
g++ -std=c++23 program.cpp -o program
18/25

警告与 Sanitizer

尤其对初学者来说，添加警告标志和 sanitizer 是好习惯，可以更早发现潜在问题。

g++ -std=c++20 -Wall -Wextra -Wpedantic program.cpp -o program
clang++ -std=c++20 -Wall -Wextra -fsanitize=address,undefined program.cpp -o program

这些选项会在后续课程中更详细解释。现在先养成“带警告编译”的习惯。

19/25

C++ 标准支持

  • 不同编译器对 C++11 到 C++26 的核心语言和标准库支持进度不同。
  • 选择标准版本时，需要同时确认编译器版本和标准库版本。
  • 工程中应记录最低支持编译器版本，避免开发者环境不一致。

Hello World

20/25

C 与 C++ 写法对比

// C
#include <stdio.h>

int main() {
    printf("Hello World!\n");
}
// C++
#include <iostream>

int main() {
    std::cout << "Hello World!\n";
}
21/25

使用全局 std 命名空间

#include <iostream>
using namespace std;

int main() {
    cout << "Hello World!\n";
}

课程展示这种写法是为了说明语法，但在实际项目中通常避免在头文件或大作用域里使用 using namespace std;。

I/O Stream

22/25

std::cout

  • std::cout 是输出流的例子。
  • 数据被重定向到某个目的地，这里目的地是标准输出。
  • C++ 流式输出使用 << 连接多个输出项。
std::cout << "value = " << value << '\n';
23/25

为什么优先使用 I/O Stream

  • 类型安全：传给 I/O stream 的对象类型在编译期已知；printf 依赖格式占位符动态匹配。
  • 更少错误：没有多余的 % token 需要与实参保持一致。
  • 可扩展：自定义类型可以重载输出运算符来支持流式输出。
24/25

常见 C I/O 错误

  • 忘记传入足够数量的参数。
  • 使用错误的格式说明符。
  • 实参类型与格式字符串不匹配，可能导致未定义行为或错误输出。
printf("long phrase %d long phrase %d", 3);

int a = 3;
printf("%s", a);
25/25

std::print

  • C++23 引入 std::print，它是基于格式字符串的改进输出方式。
  • 它保留了很多 C++ stream 的类型安全优势，同时比传统流式输出更简洁。
#include <print>

int main() {
    std::print("Hello World!\n");
}
